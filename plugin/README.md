# dsh-course-kit（界面上叫「书籍、视频摘要」）

把**一本书**和**一个视频**做成教学材料，交付三样产物：

| 产物 | 形式 | 特点 |
|---|---|---|
| 书摘 | Markdown / Word | 按章节提取演示段落，**原文逐字保留**，附作者的说明与批注 |
| 文稿与摘要 | Markdown / Word / SRT | 视频画面与音频的识别结果，带时间码 |
| 课件 | pptx | 讲义式：演示原文是主体，说明与批注作旁栏 |

Word 版按中文文稿排版：正文小四（12pt）宋体、行距 1.5；标题小三／四号（15／14pt）
微软雅黑加粗并提亮；引用的原文小四宋体，带浅底纹与左竖线。

## 可视化工作台

侧栏图标「书籍、视频摘要」，由同目录下的 `dsh-course-kit-console` 包提供。**三个页签，各自独立成一次作业**：

| 页签 | 产出 | 输入 |
|---|---|---|
| 书籍 → 书摘 | Markdown / Word | PDF ＋ 章节勾选（或全文识别）＋ 提取方式 |
| 视频 → 文稿 | Markdown / Word / SRT | 本地视频或 B 站链接 ＋ 全片（或时间段）＋ 文稿注解 |
| 课件 → PPT | pptx（可选渲染自检） | 课件规格 JSON ＋ 可选的段落／归类文件 |

做书不影响做视频，做课件也不必重跑前两者——只要段落文件已经在。
上传的素材复制到 `demo/uploads/`，原文件不动。

**产物一律落在 `course-kit\demo\out\` 下，而且一个素材一个目录**：`demo\out\文化论\`
里放这本书的书摘与 Word，中间产物（`paragraphs.json`、OCR 逐页缓存）在同目录的 `book\`
子目录里；视频同理放在 `video\` 子目录。输出目录那一栏**留空**就是这个默认值——
别退回"所有书共用一个 `out\book`"，两本书先后跑会覆盖同一份 `paragraphs.json`。

### 书籍的两种提取方式

**默认是「通用重点提取」，不需要任何配置，换哪本书都能直接跑**：不看体裁，只用段落的通用特征排序
（长度是否适中、是不是章首章末、有没有引文与数字、连接词密度、对本章词汇的代表性），
产出「关键词 + 要点摘句 + 重点段落原文」，原文逐字保留并标页码。
总结是**抽取式**的——要点摘句是从原文里挑出来的句子，不是模型写的概述；
想要那样一份概述，就换另一种方式，或把提取结果交给会话里的助手。

**「演示／说明／批注」是可选项**，只在书确实是"引一段原文再点评"的结构（写作教材、文论、评点）时才用。
这套角色是从《大师们的写作课》抽出来的，换成人类学、历史、科普往往就不成立——那时要么给这本书写预设，
要么就用默认那条路。

### 预设

每本书的段落划分都不一样，所以预设定制是常态而不是例外：

- `_默认.json` / `_默认.notes.json` 是内置通用预设，只用结构规则做初判（靠引出语识别演示段落），
  适合第一次读一本新书——先看初判结果，再决定要不要为它写一份专门的预设。
- 预设分两种，各管一件事：
  - **角色预设**（`金枝.json`）决定演示／说明／批注怎么分；
  - **书摘注解**（`金枝.notes.json`）决定章旨、技能点与单元要点怎么写。
- 书摘页签默认**配对选择**（按文件名自动带上同名注解），下面另有「分开选择角色预设与注解预设」
  的开关，需要混搭时可拆成两个下拉框。配错对是最容易被绊倒的地方——
  只有角色预设会产出 `sections.json`，注解再全也组装不出书摘。
- 每个预设下拉框旁边都有「**＋ 放入新预设**」：可以上传一份写好的 JSON，
  也可以按模板新建一份，再到 `presets/` 里填。
- 视频页签只有注解预设，没有角色预设——视频没有"哪几段是演示段落"这个问题。

### 作业的跳过与中止

每一步声明它需要的前置产物。前置不在就跳过并写明原因；必需步骤失败则后续一律标为跳过，
原因优先用脚本自己写的那句 `message`（例如"这是扫描件，需要先做 OCR"），没有才退回
「上一步失败：某步」。不会出现"某个文件不存在"这种无从下手的失败，也不会把工具的限制
说成使用者的顺序错误。

## 开发须知：宿主半的改动需要重启应用

Loader 会把加载过的宿主模块留在 ESM 缓存里，**改文件内容、改 `main` 字段、重挂 bundle 都不会
重新导入**。客户端半（`lib/client.js`）刷新页面即可，宿主半（`console/lib/main.js`、
`plugin/lib/host.js`）必须重启 DSH 才生效。

因此控制台的实现整个放在 `console/lib/main.js` 里，不跨包 import——改动时换个入口文件名
就能在当前进程里生效，不必去猜哪些依赖被缓存了。

改动后先跑 `node console/test/smoke.mjs` 自检：它直接 import 模块并注入假的 runner，
在不启动任何 Python 进程的前提下，把路由、预设读写、越权拦截与作业链条逻辑逐条走一遍。
（当前沙箱下 node 删不了工作区里的文件——删就崩，退出码 `0xC0000409`，所以加
`COURSEKIT_SMOKE_NO_RM=1` 跳过收尾清理，跑完用 Python 收残渣；详见 HANDOFF.md 第三节。）

## 它解决的具体问题

教材和网课里最值得讲的是**成段的原文**，而原文最怕经手模型——转述一次就走样，
而且走样得很难发现。所以这个插件的做法是：

- **搬运**交给 Python 脚本：PDF 按缩进与页码切段，ASR 按时间码出句，全部逐字。
- **判断**交给你（模型）：哪几段是演示、哪几段是说明与批注，章旨是什么。
- **判断的结果**写进 `presets/*.json`。换书换视频只改 JSON，脚本不用动。

这就是「预留的接口」：`chapters` 选章，`overrides` 选段，`sections` 选时间区间。

## 依赖

- Python 3.10（可用 `COURSEKIT_PYTHON` 覆盖），第三方包装在工作区 `.pylibs`：
  `pymupdf`、`python-pptx`、`yt-dlp`、`sherpa-onnx`、`rapidocr-onnxruntime`、`onnxruntime`
  （装法见 HANDOFF：**必须 `--only-binary=:all:` 并钉死版本**，否则 pip 的解析器会空转十几分钟）
- ffmpeg（`video_fetch.py` 会自动找几个已知路径，或用 `DSH_FFMPEG` 指定）
- 识别模型复用 DSH 自带的 SenseVoice，不额外下载、不上传音频
- 视频下载走 B 站 `playurl` 接口：网页端有反爬（HTTP 412），接口带浏览器 UA + Referer 可用

## 扫描件：本地 OCR

书单上的书**大多是扫描件**——PDF 每页一张图，一个字符也取不到，只能逐页认字。
`pdf_ocr.py`（工具 `coursekit_book_ocr`、控制台的「扫描件：先做 OCR 再提取」）就是干这个的：

- **全本地**：RapidOCR（PP-OCRv4 的 ONNX 模型，随包分发）跑在 CPU 上，不联网、不上传音频图像；
- **逐页决定**：某页有文字层就直接读它，没有才渲染识别——混合型 PDF 不用挑；
- **一页三四秒**：识别占八成、检测一成，4 线程并行（识别本身已经吃满核，线程再多不划算）；
  只勾章节就只识别那几章，几百页的整本要跑十几到几十分钟；
- **可以中断**：逐页结果写在 `<out>/ocr_pages/`，再跑一次跳过已识别的页；
- **产物同构**：paragraphs.json / paragraphs.md 与 `pdf_extract.py` 一模一样，
  digest／curate／book_report／课件那几步一个字都不用改；
- **版式清理**：页眉、书眉、页码在切段前清掉（"短 + 没写到右边"就是居中标题），
  缩进阈值按 OCR 估出的字宽算（行框会抖，不能拿最小 x 当左边界），
  汉字之间的半角标点转全角，两三个连字符并回 `——`。

质量上：印刷体中文书页的识别置信度普遍在 0.98–1.00，错字主要是形近字与生僻标点。
真要较真，可以把 `paragraphs.md` 与 PDF 对照着校一遍——但不要用模型去"顺"原文，
那正是这套流程要避免的事。


## 关于课件风格

面向大学课堂，取向是讲义而不是发布会：原文占整幅左侧、字号最大，
说明与批注退到右侧窄栏；没有图标和色块拼贴，只有一条分隔线和一个页码；
标题写具体的东西（「兔头、香椿，和一只铝饭盒」），不写「从 X 到 Y」「全流程：」这类总结腔。

`coursekit_deck_preview` 会把 pptx 画成 PNG 并报出每个文本框的
「需要高度 / 可用高度」——**溢出数不为 0 就不要交付**。
字号估算是估算，渲染结果才是事实。
